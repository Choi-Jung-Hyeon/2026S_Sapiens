# 2026S_Sapiens
신인류AI사피엔스경험디자인 최재붕 교수님

## PackCheck

여행 조건을 고르면 준비물 체크리스트를 만들어 주는 한 페이지 웹앱.

배포 주소: https://choi-jung-hyeon.github.io/2026S_Sapiens/

`main` 브랜치에 푸시하면 1~2분 뒤 위 주소에 자동 반영됩니다 (GitHub Pages).

## 화면에서 할 수 있는 것

1. 여행 조건 6가지(목적지 / 국가 / 월 / 기간 / 성격 / 인원)를 고르고 리스트를 만듭니다.
2. **필수 준비물**이 카테고리별로 나오고, 체크(진행률 반영)와 삭제(X)가 됩니다.
3. 목록 맨 아래 입력창에 **직접 챙길 것**을 넣으면 `직접 추가` 칸에 쌓입니다. (엔터 또는 `추가` 버튼)
4. 아래쪽 **추천 카드**는 `추가` 로 필수 목록에 올리거나 `필요 없어요` 로 뺍니다.
5. 지우거나 뺀 직후 토스트의 **`실행 취소`** 를 5초 안에 누르면 원래 자리로 돌아옵니다.
6. 하단의 **알림 받기 / 공유하기 / 테스트 기록 복사** 버튼.

리스트는 브라우저에 저장돼서 새로고침해도 남습니다. 오른쪽 위 `처음부터 다시` 로 지웁니다.

## 2차 개선 (1차 관찰 테스트 반영)

| 항목 | 1차 | 관찰 결과 | 2차 |
|---|---|---|---|
| 접이식 우산 | 추천 | 노출된 사람의 절반이 직접 추가 | **필수로 승격** |
| 명함 | 추천 | 노출 2회 / 추가 0회 | **규칙에서 제거** |
| 여권 사본 | 필수 | 해외 테스터 70%가 직접 삭제 | **추천으로 강등** |

함께 넣은 것: 직접 항목 추가, 실행 취소, 출발 알림 수요 확인 버튼,
오세아니아 계절 반전(아래 참고), 테스트 기록 3줄 확장.

## 팀원용 3단계

1. 코드 받기: `git clone https://github.com/Choi-Jung-Hyeon/2026S_Sapiens.git`
2. 수정하기: `index.html`을 브라우저로 열어서 확인하고, AI에게 수정 요청
3. 올리기: `git add . && git commit -m "2차 개선" && git push`

## 어느 파일을 열어야 하나

| 파일 | 언제 여는가 | 무엇이 들어 있나 |
|---|---|---|
| `rules.js` | **준비물을 바꿀 때 (대부분 여기)** | 준비물 39개 규칙표, 국가 목록, 콘센트 타입 |
| `index.html` | 문구를 바꿀 때 | 화면 뼈대와 버튼 이름 |
| `styles.css` | 색을 바꿀 때 | 맨 위 `:root` 의 색상값만 고치면 전체 반영 |
| `app.js` | 기능을 바꿀 때 | 화면 동작, 공유, 이벤트 기록 |

네 파일은 반드시 같은 폴더에 두세요. 빌드나 설치는 필요 없고, `index.html`을 더블클릭하면 그대로 열립니다.
(`npm`, 번들러, `type="module"`, `fetch` 전부 쓰지 않았습니다. 쓰는 순간 더블클릭이 막힙니다.)

### 준비물 하나 추가하는 법

`rules.js` 의 `// ===== 규칙 테이블 시작 =====` 아래에 한 줄을 넣으면 됩니다.

```js
{ id: 'slippers', name: '실내용 슬리퍼', category: '기타', type: 'suggest', qty: null,
  reason: '숙소에서 신을 신발이 필요합니다',
  when: function (t) { return t.nights >= 2; } },
```

`type` 이 `'auto'` 면 리스트에 바로 들어가고, `'suggest'` 면 추천 카드로 나옵니다.
관찰 테스트에서 "다들 직접 추가하더라" 싶은 항목은 `'suggest'` → `'auto'` 로 한 글자만 바꾸면 됩니다.
`when` 에 쓸 수 있는 조건은 같은 파일의 주석에 정리돼 있습니다.

### 계절 조건을 쓸 때 (중요)

오세아니아는 남반구라 계절이 반대입니다. **계절 조건은 `t.month` 대신 `seasonMonth(t)` 를 쓰세요.**
`seasonMonth` 는 오세아니아일 때만 월을 6개월 이동시켜 돌려줍니다. (7월 → 1월, 12월 → 6월)

```js
{ id: 'thermos', name: '보온병', category: '기타', type: 'suggest', qty: null,
  reason: '기온이 낮은 시기입니다',
  when: function (t) { var m = seasonMonth(t); return m >= 11 || m <= 2; } },
```

콘센트 타입처럼 계절과 상관없는 지역 규칙은 `t.country` 를 그대로 보면 됩니다.
화면 요약과 테스트 기록에 찍히는 월은 언제나 실제 출발 월입니다.

### `직접 추가` 는 규칙에 넣지 마세요

`직접 추가` 는 사용자가 입력창으로 넣은 항목이 모이는 칸입니다. 규칙표의 `category` 로는 쓰지 않습니다.

## 측정 방법

Google Analytics는 쓰지 않습니다. 데이터 반영에 하루가 걸려 수업 일정에 맞지 않아,
**팀 내부 + 지인 관찰 테스트**로 KPI를 측정합니다.

- 테스터가 다 쓰고 나서 결과 화면 맨 아래 **"테스트 기록 복사"** 를 누르면 아래 형식의 텍스트가 복사됩니다.
  이걸 단톡방에 붙여넣어 주면 집계가 끝납니다.

```
[PackCheck 테스트기록]
조건: 해외 / 영국 / 8월 / 4~6박 / 관광 / 2명
자동 생성 항목: 17개
추가한 추천 항목(2): 선크림, 선글라스
거절한 추천 항목(1): 목베개
삭제한 필수 항목: 없음
직접 추가한 항목(1): 렌즈 세척액
되돌리기 사용: 1회
알림 버튼: 눌렀음
체크 완료: 15 / 18
```

공유 링크로 들어온 테스터는 첫 줄이 `[PackCheck 테스트기록 / 공유링크 진입]` 으로 나옵니다.
`실행 취소`로 되돌린 항목은 기록에서 빠지므로, 집계에는 최종 결과만 남습니다.

- 개발 중 동작 확인은 브라우저 개발자도구(F12) → Console 탭에서 `[track]` 로그로 볼 수 있습니다.
  기록되는 이벤트: `list_generated`, `suggestion_added`, `suggestion_rejected`,
  `essential_removed`, `item_checked`, `list_shared`, `shared_link_opened`,
  `custom_item_added`, `undo_used`, `notify_cta_click`
  (1차와 2차를 비교해야 하므로 기존 이벤트의 이름과 파라미터는 바꾸지 않습니다.)
- 나중에 측정 도구를 붙이려면 `app.js` 의 `track()` 함수 안만 바꾸면 됩니다.
  이벤트 발생 지점은 코드 곳곳에 그대로 남겨 두었습니다.
- **"출발 1시간 전 알림 받기"** 는 수요만 확인하는 버튼입니다. 실제 알림 기능은 없고,
  누르면 안내 문구만 뜹니다. 전화번호를 받거나 서버로 보내는 동작은 전혀 없습니다.

### 이 텍스트에서 뽑는 지표

| 지표 | 세는 법 | 목표 |
|---|---|---|
| 추천 항목을 1개 이상 추가한 비율 | `추가한 추천 항목` 이 `없음` 이 아닌 사람 | 40% |
| 필수 항목을 하나도 지우지 않은 비율 | `삭제한 필수 항목: 없음` 인 사람 | 70% |
| 직접 추가를 쓴 비율 | `직접 추가한 항목` 이 `없음` 이 아닌 사람 | 2차에서 처음 측정 |
| 알림 수요 | `알림 버튼: 눌렀음` 인 사람 | 2차에서 처음 측정 |

`되돌리기 사용` 이 잦으면 삭제 버튼을 잘못 누르고 있다는 뜻이라, 3차 때 볼 신호입니다.
직접 추가한 항목을 지운 것은 `삭제한 필수 항목` 에 들어가지 않습니다.
사용자가 스스로 넣은 항목이 섞이면 위 두 번째 지표가 1차와 비교되지 않기 때문입니다.
